# @pragmatiks/lint

Library-only eslint flat config and bundled semgrep rules for Pragmatiks engineering principles.

This package has no `bin` entry. Command-line integration belongs in `pragma-cli`.

## Peer dependencies

**Requirements:** Node `^22.13.0 || >=24`.

**Package-wide** (the root entry and `/eslint-config/next`):

| Package                 | Range      |
| ----------------------- | ---------- |
| `eslint`                | `^10.11.0` |
| `typescript-eslint`     | `^8.70.1`  |
| `eslint-plugin-sonarjs` | `^4.0.0`   |
| `eslint-plugin-unicorn` | `^64.0.0`  |

**`/eslint-config/next` only** (optional peers; install them when you use `@pragmatiks/lint/eslint-config/next`):

| Package                 | Range     | Why                                                                  |
| ----------------------- | --------- | -------------------------------------------------------------------- |
| `@tailwindcss/node`     | `~4.3.3`  | Compiles class strings with the project's own Tailwind design system |
| `tailwindcss`           | `~4.3.3`  | Version check against the project                                    |
| `@tailwindcss/postcss`  | `~4.3.3`  | Version check against the project                                    |
| `@eslint/css`           | `^2.0.0`  | Lints `.css` files                                                   |
| `eslint-plugin-react-x` | `^5.20.8` | Leaked conditional rendering (typed)                                 |

The project's `tailwindcss`, its `@tailwindcss/postcss` and the `@tailwindcss/node` this package imports must be the same version, or loading the config throws. `@eslint/css-tree` is a regular dependency.

## `@pragmatiks/lint/eslint-config`

The base config for JavaScript and TypeScript, also exported from the package root:

```ts
import { PRAGMATIKS_LINT_FILES, pragmatiksConfig } from "@pragmatiks/lint";

export default pragmatiksConfig();
```

Every object except the global ignores, the sonarjs and unicorn recommended presets included, applies only to `PRAGMATIKS_LINT_FILES` (`**/*.{js,jsx,mjs,cjs,ts,tsx,mts,cts}`), so the config composes with configs for other languages such as CSS.

## `@pragmatiks/lint/eslint-config/next`

In the app's `eslint.config.mjs`:

```js
import nextVitals from "eslint-config-next/core-web-vitals";
import nextTs from "eslint-config-next/typescript";
import { pragmatiksNextConfig } from "@pragmatiks/lint/eslint-config/next";

export default await pragmatiksNextConfig([...nextVitals, ...nextTs], {
  rootDir: import.meta.dirname,
  tailwindStylesheet: "app/globals.css",
});
```

Run it with `eslint . --max-warnings 0`; the Next presets report some rules as warnings.

Composition, in order:

1. The Next configs. Objects without `files` get the glob of the one object that registers `jsx-a11y`; the config throws unless there is exactly one. Ignore-only objects stay global.
2. `pragmatiksConfig()` on `**/*.{js,jsx,mjs,cjs,ts,tsx,mts,cts}`. Its typescript-eslint parser replaces Next's Babel parser on JavaScript files too.
3. The frontend rules on the `jsx-a11y` glob.
4. `react-x/no-leaked-conditional-rendering` on `**/*.{ts,tsx,mts}` with typed linting (`projectService`, `tsconfigRootDir: rootDir`).
5. The CSS rules on `**/*.css` (`css/css`, tolerant parsing).

Every config object you add after the result must set `files`, for example `files: PRAGMATIKS_LINT_FILES` from `@pragmatiks/lint`. An object without `files` also applies to `.css` files, and JavaScript rules crash on them.

### Operating notes

- **Not `--cache`-safe across stylesheet edits.** Class checks depend on the stylesheet, which ESLint's cache does not track.
- **Restart after editing a stylesheet.** The design system loads when the config is built, so persistent ESLint processes and editor servers keep the old theme until restarted.
- **Tailwind bumps.** Rerun the class-token corpus (`tests/next-class-tokens.test.ts`, AC-1) at the new version before widening the `~4.3.3` peer range. The config uses Tailwind's `__unstable__loadDesignSystem`; a load canary and the version check fail fast when it changes shape.

### Focus patterns

- **P1**, the only class pattern: `focus-visible:outline-hidden focus-visible:ring-2`. Optional extras: one project ring color (a theme color that is not from Tailwind's default palette, `@theme inline` colors included, `ring-(--x)` or `ring-[var(--x)]`, with no `/` modifier), one `ring-offset-<n>` and one project offset color; a `ring-offset-<n>` above 0 needs the offset color, and `ring-offset-0` allows it but needs none. Every in-scope token has exactly the `focus-visible` variant and no `!`.
- **C1**, the only CSS pattern: every selector in the list ends in `:focus-visible` (an `@variant focus-visible` block counts as one), and the declarations are exactly `outline: <non-zero width> solid var(--token)` plus an optional `outline-offset`, without `!important`.

### Known false positives

Fix these by rewriting the code:

- In-scope styling outside P1/C1: decorative rings, `!important` shadows, split patterns, and decorative `box-shadow` in unlayered CSS or `@keyframes`.
- Class-like words in prose strings.
- `a...b` in URLs outside `href`/`src`/`action`.
- Decorative `box-shadow` in a stylesheet that its importer layers (`@import "./x.css" layer(components)`): layers are judged per file, so it counts as unlayered.
- Controls paired with a design-system label component (`<Label htmlFor>`): only a lowercase `<label>` pairs with a control. Use `<label>` or `aria-labelledby`.
